# TradingCalculator v2 改造说明

## 〇、v2.1 补充：期权情绪改为“可选辅助”

背景：做的是股票波段，目前不交易期权，Put/Call 和 IV Rank 只作辅助参考。

| 项目 | v2.0 | v2.1 |
|---|---|---|
| 页面标注 | “期权情绪” | “期权情绪（可选辅助）”，并说明：有数据时补充情绪判断，没有数据时自动跳过，不影响基础点位计算。不承诺填写后更准。 |
| 默认值 | 第一次打开会自动载入演示数据（含 0.68 / 52） | 输入框默认空白；期权示例值只在点“载入示例数据”时填入 |
| 缺失 / 无效 / 0 | 缺失跳过；无效值（负数、IV Rank > 100）会报红色错误并让整张阶梯不可用 | 两项可以单独填或都不填；空白、无效值都跳过，不会变成 0，只给黄色提示，不影响阶梯；真实填写的 0 保留并参与判断 |
| 权重 | 和成交量放在同一个评分里：Put/Call 一项就能把仓位乘数从 1.0 推到 1.3 | 从成交量评分中分离。成交量照旧决定技术面乘数（×0.6 / ×1.0 / ×1.3）；期权只在这之上做**相对**调整：Put/Call ≥ 1.1 买 +3% 卖 −3%，≤ 0.7 买 −3% 卖 +3%，IV Rank ≥ 60 两侧 −2%，合计限制在 ±5%（20% → 21%，不是 25%）。C 档不调整 |
| 对结论的影响 | 期权情绪可以算作“建议减仓”的确认；缺失时止盈置信度降为“低” | 期权情绪不改变 A–E 价格点位，不算止盈确认条件，不单独触发买卖；只在理由里作为“辅助、不计入确认”列出。置信度只看技术面数据是否完整 |
| 结果区 | 只列评分 | 单独一行写明哪些期权指标参与了、哪些被跳过（未填写 / 无效值 / 属于其他股票），以及买卖两侧各调整了多少 |
| 换股 | 期权数据属于别的股票时清空 | 只要代码变了就清空 Put/Call、IV Rank 和期权来源 |
| 文案 | 方法说明、获取提示里有“需填入”等表述 | 全部改为“可选，不填也能计算”；方法说明注明参数为暂定值、未经回测 |

验证（全部是自动化测试，`npm test` 53 项通过）：全部留空 → 完全按技术面且不报提醒；只填一项 → 只用这一项；真实 0 → 保留并参与；无效输入（文字、负数、IV Rank 150）→ 跳过、不变 0、阶梯照常可用；切换股票 → 清空（网页实测）；11 × 8 种期权组合 × 3 种量能 × 5 个价位下 A–E 价格、到达档位和所在区域完全不变；每档仓位相对技术面的变化都在 ±5% 以内，C 档不变；11 个历史场景里“期权中性 / 追涨 / 恐慌”三种假设的止盈判断与“不填期权”100% 相同。

注意：卖出累计上限 100%、买入累计上限 90% 仍然有效。期权调整让前面几档变大时，最后一档（E2 或 A1）拿到的剩余额度会相应变小，页面会标“已按上限截断（原 x%）”——这是总额上限造成的，不是期权调整超过了 ±5%。


分支：`feature/take-profit-api`（基于 `6d6ab69`）。原有界面、A–E 阶梯公式和“自动获取行情”都保留；计算逻辑从 `index.html` 抽到 `core.js`，网页、接口、命令行、测试共用这一份。

## 一、修改前后差异

### 第一阶段：计算问题修复

| # | 原来的问题 | 现在 |
|---|---|---|
| 1 | 卖出比例 5+10+15+40+20=90%，放量时 ×1.3 → 累计 117%；`Math.round` 后显示 118%。买入侧同理会超过 100%。 | D1→E2 按价格由低到高累计，**不超过卖出上限（默认 100%）**；超出的档位只拿剩余额度并标“已按上限截断”。买入侧 C2→A1 累计不超过 100% − 保留现金（默认 10%，和原有“保留 10% 现金”的提示一致）。 |
| 2 | 没说每档比例是占什么的。 | 新增“卖出比例基数”选项：**初始持仓**（默认，每档占计划开始时的股数）或**剩余持仓**（每档占触发当时剩下的股数，累计 = 1 − Π(1 − p)）。阶梯上每档显示“本档 % · 累计 %”，止盈模块按此换算成股数，已有卖出记录先抵扣低档位。 |
| 3 | 切换股票后 Put/Call 和 IV Rank 原样保留，会被当成新股票的数据。 | 改代码时自动清空期权数据；每个行情字段记录“属于哪只股票”，换股后旧数字会触发红色错误“数据属于 MU，与当前代码 NVDA 不一致”，阶梯变灰、止盈分析停用，直到重新获取或逐个改掉。持仓信息也按代码分开存。 |
| 4 | `num()` 把空值变成 0：Put/Call 留空 = 0 ≤ 0.7 → 被当成“追涨”，卖出加分；页面默认还带着演示值 0.68 / 52。 | 缺失一律为 `null`，评分里跳过，不加不减。期权示例值只在点“载入示例数据”时填入；旧版本残留在真实代码下的 0.68 / 52 会被识别并清空。（v2.1 进一步调整，见第〇节） |
| 5 | 只有一句“获取于 …（行情时间未提供）”。 | 新增数据来源表：最新价格 / 日线指标 / 期权情绪分别显示来源、数据时间、延迟；价格超过 15 分钟标 ⚠；日线停留超过 4 天标 ⚠；旧服务没给时间戳时明确写“服务未提供，延迟未知”；交易时段内获取会提示当日成交量可能未完结。 |
| 6 | 只检查了布林带顺序和现价。 | 增加：必填/正数检查、IV Rank 0–100、Put/Call > 0、系数顺序（否则档位颠倒）、比例 0–100%、计算后档位严格递增检查、现价离布林带超过 3 个带宽（多半是数据不同步）、EMA 与现价相差 50% 以上。错误（红）与提醒（黄）分开显示。 |
| 7 | 没有测试。 | 自动化测试（见下，v2.1 共 53 项）。 |

另外发现并修复：

- **趋势修正导致档位顺序颠倒**：多头排列且 EMA50 贴近下轨时，原公式会把 B2 拉到 B1 下面。回放发现这在强势上涨里很常见（TSLA 2016-12 至 2017-03 有 20/61 天、AAPL 2016-12 至 2017-02 有 15/46 天）。现在被修正的档位会限制在相邻档位之间，并在页面上说明。其他情况下 11 个点位与原版逐档一致（有回归测试）。
- 基准比例填 0% 时原版会强制变成 1%，现在保持 0。
- 快照列表里的代码改为转义后显示。

### 第二阶段：止盈分析模块（新增第 3 节）

- 输入：账户类型（长期 / 波段）、当前股数、平均成本、保留核心仓 %、计划基数（可选）、财报日期、其他事件、原定退出价、原退出计划文字、已实现的部分卖出记录（日期 / 股数 / 价格 / 档位）。
- 输出：D1–E2 每档的候选止盈价、目标累计 %、建议股数、预计金额、该笔利润、执行后剩余股数；汇总本次建议卖出、已实现利润（记录 + 本次）、浮动盈亏、剩余持仓风险（回落到 C1 或长期账户 A2 的回吐金额、距成本的缓冲、财报跳空提示）。
- **三个选项始终都在**：分批止盈 / 继续持有 / 无需操作，并标出当前倾向和理由。
- **价格到达档位只是“候选”**，至少还需要一项确认才会给出“建议减仓”：放量、财报/重要事件临近、空头排列下的反弹、或已到达你原定的退出价（v2.1 起期权情绪不再算确认条件）。多头排列且没有放量时减一分（沿上轨上行很常见）；长期账户的 D 档默认只作提醒；现价低于成本时一律“无需操作”。
- 成交量数据缺失或盘中未完结时置信度标为“低”（期权数据缺失不影响置信度）。

### 第三阶段：给 Muse 的接口

- `core.js`：全部纯函数，没有 DOM、网络或存储依赖。`analyze()` 输出统一的 `tradingcalculator.analysis.v1` JSON。
- `api/worker.js`：Cloudflare Worker，`GET /v1/analysis`（公开只读，拒绝持仓参数）、`POST /v1/position-analysis`（Bearer token 保护）、`GET /?symbol=`（兼容旧网页并补上时间字段）。
- `cli/analyze.js`：离线命令行，输出同一 JSON。
- 网页第 5 节：一键复制同一格式的 JSON（公开版不含持仓）。
- 详细说明、部署步骤和 Muse 的几种接法见 `docs/API.md`。**接口还没部署，Muse 还没接通。**

### 第四阶段：验证

`docs/验证报告.md`（由 `node tests/report.js` 生成）。11 个历史场景：上涨趋势 2 个、急跌 3 个（含 2008 年和 2015-08-24）、横盘 2 个、财报跳空 3 个、高波动 1 个；每个场景再跑 9 种数据条件（期权中性/追涨/恐慌、现价 ±0.3%、去掉成交量、去掉 EMA200、剩余持仓基数、长期账户）。

## 二、测试结果

```
npm test   →  53 passed, 0 failed
```

- `tests/core.test.js`（31，含 7 项期权情绪专项）：数字解析、点位回归、保序修正、比例上限（两种基数）、缺失期权、换股串号、输入验证、时效、盘中未完结、区域定位、止盈判断的各种分支、零碎股、公开/受保护 JSON 边界、指标计算；并与第三方实现（R `TTR::BBands`，数据集自带列）逐日对比，最大偏差 < 1e-6。
- `tests/worker.test.mjs`（9）：模拟 Twelve Data，验证路由、拒绝持仓参数、token 校验、no-store、密钥不泄露、上游限流/代码不一致、盘中丢弃未完结日线、兼容旧格式。
- `tests/scenarios.test.js`（13）：5 类场景的不变量（4390 个场景×条件×交易日，违反 0 次）、稳定性阈值、上涨趋势不因单纯触及上轨而建议卖出、急跌日不建议止盈、跳空越档、无未来数据、结果可复现。

稳定性要点（详见报告第 3 节）：

- 期权数据不填、中性、追涨、恐慌四种情况的止盈判断 100% 相同（v2.0 时追涨/恐慌假设会让 64–100% 的日子判断一致）；比例基数只改变股数，不改变判断（100%）。
- 现价 ±0.3% 时，止盈判断一致率 90–100%；但“最接近哪一档”只有 72–100% 一致——相邻档位本来就很近，这个标签对小波动敏感。
- 去掉成交量后，判断一致率最低降到 64%（TSLA 2018-08 财报场景），说明量比是影响最大的单一因子。

## 三、尚未解决的问题

1. **接口未部署、Muse 未接通**：需要你在 Cloudflare 部署并设置密钥；Muse 的运行环境我不知道，接法见 `docs/API.md` 第 4 节。
2. **我没能推送到 GitHub**：这个会话没有该仓库的写权限。改动在本地分支里，已打包成 zip 和 patch 发给你。
3. **验证数据偏旧**：这台机器访问不到最新行情源（Yahoo/Stooq/Twelve Data 被拦截，金融数据接口余额为 0），只能用公开数据集里 2007–2018 年的真实日线。历史 Put/Call 和 IV Rank 拿不到，期权辅助参数（±3% / −2% / ±5%）是暂定值，只用假设值验证了“不越界、不改点位、不改结论”，没有验证它是否有用。
4. **量比阈值带来逐日翻转**：TSLA 上涨场景 61 天里判断变了 18 次，主要是量比在 1.5 上下来回。可以考虑“近 3 天内有 2 天放量”或用 3 日均量平滑——这会改变原算法，所以没有擅自改，等你决定。
5. **只看收盘价/现价，不看日内高低点**：2015-08-24 盘中跌破 A1、收盘几乎收回，阶梯上看不出来。跳空（例如 TSLA 2018-09-28 一天越过 6 档）阶梯无法防守。
6. **新旧 Worker 指标可能略有差异**：新 Worker 用 300 根日线自己计算布林带/EMA（EMA200 以前 200 根 SMA 为种子），旧 Worker 用 Twelve Data 的指标接口；两者在小数位上可能不同，盘中新 Worker 不把今天未完结的日线算进去。
7. 已实现利润按平均成本法；券商用 FIFO 或指定批次时会不同（卖出记录可以填 `costBasis` 覆盖，网页暂未提供这个输入框）。
8. 原退出计划的文字不会被自动解析，只原样显示；原定退出价（数字）会参与判断。
9. 所有系数、阈值（1.5 倍量、0.7/1.1 Put/Call、IV Rank 60、确认分数规则）都是起点估计，没有经过系统性回测。

不自动下单，不修改任何券商账户。
